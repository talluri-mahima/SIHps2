# Local PaddleOCR integration

The application supports explicit `rapidocr` and `paddleocr` CPU providers. It does not silently substitute one for the other. All critical candidates require officer confirmation; OCR confidence is recognition confidence, not authenticity confidence.

PaddleOCR runs in `.venv-paddle`, separate from the API dependencies. Create that environment with `python -m venv .venv-paddle`, install `requirements-paddle.lock` with its Python interpreter, then run `.venv-paddle\Scripts\python.exe scripts/paddle_worker.py --provision` with network access to download the two named model bundles. `requirements-paddle.in` records the direct dependencies. Provisioning processes no application document. The worker uses PP-OCRv5 mobile detection and English recognition. These English models do not establish support for regional-language documents.

After provisioning, set `AICTE_OCR_PROVIDER=paddleocr` and restart the API. `AICTE_PADDLE_PYTHON` can specify the isolated interpreter. Models are copied to ignored `.data/paddle-models/` and request-time worker initialization requires those local paths. The worker has a 180-second per-page timeout and the enclosing document parser retains its 300-second document deadline. Long scans can time out and require retry/manual review. This is subprocess separation, not an operating-system network sandbox.

Native text remains the default when present. `AICTE_OCR_FORCE=true` explicitly replaces the native text path with rendered-page OCR for evaluation of weak text layers; it increases latency. Do not assume native text is complete merely because it exists. Page artifacts record the actual extraction method.

Layout support currently adds unique same-row label/value associations, page-level keyword document suggestions, source-located floor notation and expiry-label review hints. A `G+3` mention is expanded as a **review hint**, not automatically accepted as covered floors. Adjacent table cells, multiple candidates, ambiguous numeric dates, identity linkage and legal document scope can still require human review.

Unit tests cover OCR output shape, finite scores, source coordinates, provider rejection, ambiguous row abstention and hints that never become automatic scope claims. Real model execution and real-document results must be recorded separately from these tests. No custom model training or independent accuracy benchmark is implied by installation.

## Tested laptop configuration

On 28 October 2026, PaddleOCR 3.7.0 and PaddlePaddle 3.3.1 completed both real development pages with the provisioned model hashes recorded in `reports/ocr-provider-rehearsal.json`. The worker reuses one loaded model instance within a document. oneDNN acceleration is explicitly disabled because this Windows runtime raised a PIR attribute conversion error. The final run took approximately 107 seconds for the fire page (including worker startup) and 121 seconds for the dense occupancy page. The corresponding RapidOCR observations took approximately 8 and 19 seconds. These two pages do not establish comparative accuracy or a latency service level.

`scripts/paddle_upload_rehearsal.py` also passed the actual local application path: named password login, synthetic scanned upload, Defender result, three exact expected fields, all critical fields unconfirmed, authorized stored preview and offline signature check. Its report is `reports/paddle-upload-rehearsal.json`. It requires the ignored local accounts file and the fixture generated by `scripts/document_check.py`; it creates a clearly named synthetic application. The test never establishes issuer authenticity.
