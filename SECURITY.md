# Development security boundary

This milestone is a loopback-only local prototype with synthetic demonstration records and a separate public-layout evaluation corpus. It is not approved for deployment with confidential institutional evidence.

## Enforced now

Application and object authorization; explicit officer/auditor assignments; rejected cross-tenant access; opaque hashed session tokens; HttpOnly SameSite cookies; expiry and logout revocation; origin/host checks; role checks on every reviewer mutation; strict request fields; upload size/type checks; no user-controlled external URL fetching; bounded parser child process; active-PDF structure checks; immutable evidence versions; critical-fact confirmation; row-version review checks; stale export blocking; hash-linked transactional audit; production startup refusal.

The synthetic demo shortcuts intentionally allow switching personas and automatically assign the known demo officer/auditor to applications created by the synthetic applicant. These are not production provisioning policies. Password login exists for integration development; initial demo accounts have random unrevealed passwords and use local persona sign-in. Rate limiting is in-process and not production-grade.

## Required before release

OIDC/SSO and hardened recovery/session lifecycle; PostgreSQL RLS tested with non-owner roles (local versioned migrations are implemented); OS-level parser network/memory isolation; mandatory deployed malware provider (optional local Defender adapter is implemented); private object store and encryption/key management; approved signature trust roots and revocation evidence (offline cryptographic checks are implemented); retained independent audit copies; controlled rule author/approver workflow; privacy/retention/legal-hold design; source agreements; authorized deployment security review.

Page previews are generated by bounded parser subprocesses; the API serves stored derivatives. Subprocess separation does not enforce OS-level network/memory isolation. The optional PaddleOCR worker uses explicit local model paths after provisioning, with no remote OCR API. Multipart transport can spool input before application limits; enforce HTTP/body limits at the server/proxy before production. The local database/global write lock supports one development process, not horizontally scaled operation. Immutable rows/hash chains are not protection against a privileged database/file administrator. File writes and DB commits are not one atomic storage transaction; orphan-object cleanup is pending.

Report issues privately to the repository maintainers through an available private channel. Do not publish real evidence, credentials or exploit sensitive live systems. This file establishes no legal or regulatory compliance certification.
